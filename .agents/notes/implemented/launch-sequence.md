# Agent Note: 保持两幕开场可独立调试并无缝串联

Status: implemented

## 决定

品牌手账和秋招专场是两个独立开场，分别由 `debug=-1` 与 `debug=-2` 重播；
`debug=-3` 固定重播品牌手账、秋招专场和主页面组成的完整链路。正常访问仍由
本地已播放状态与当前路径决定是否串联两幕。

第一幕开始收页时，若下一幕是秋招专场，`App` 先将第二幕以未激活状态挂在第一幕
下方。第二幕此时只提供背景，不启动卡片、文案或完成计时；第一幕卸载并把
`launchScreen` 切换为 `autumn` 后，第二幕才正式播放。

## 问题与约束

第一幕使用裁切收页。若第二幕等第一幕卸载后才挂载，收页期间会露出隐藏的主页面或
空白背景，转场出现断层。若第二幕预挂载时立即启动，它可能在第一幕结束前消耗演出
时间，导致用户只看到第二幕的尾段。预挂载状态和播放状态因此必须分开。

单独调试参数不串联其他动画，避免调整其中一幕时每次等待完整链路；只有 `debug=-3`
强制忽略已播放状态并串联两幕。

## 替代方案与取舍

- 第一幕结束后再渲染第二幕：状态较少，但裁切退出无法直接露出下一幕。
- 预挂载后立即播放第二幕：实现直接，但两幕时间线互相侵占。
- 合并为一个 GSAP 时间线：可精确控制时序，但会破坏两幕独立调试和跳过能力，并让
  `App` 更难根据路径与本地状态选择开场。

当前方案增加了 `isAutumnPrepared` 与 `active` 两个状态，但保留两幕的独立生命周期，
并把串联规则集中在 `src/utils/launchSequence.ts`。

## 验证与重审条件

`scripts/test-intro-debug-mode.mjs` 固定三个调试参数的解析契约，
`scripts/test-launch-sequence.mjs` 固定单幕与完整串联的选择规则。视觉验收需确认第一幕
收页时直接露出第二幕背景，且第二幕卡片只在第一幕卸载后开始出现。

如果开场增加第三幕、需要跨路由恢复播放进度，或多个开场共享更复杂的取消与跳过逻辑，
应重新评估是否由显式状态机统一管理，而不是继续增加布尔预挂载状态。
