# 更新与已有项目

## 项目文件

初始化脚本只创建缺失文件，不做三方合并，也不保存文件版本清单。已有 `AGENTS.md`、`PRODUCT.md`、Notes、hooks 内容和权限保持不变。已有目录符号链接不会被穿透写入。

已有有效 `core.hooksPath`（包括全局配置）、默认 Git hooks、`.githooks/` 目录或 worktree 时，不自动更改 hooks 配置。新增模板仍可供维护者审查；不要把“模板已存在”当成“hook 已启用”。

## 更新 Skill

用户要求更新时，先检查 Skill 来源、项目/全局范围以及是否有本地定制。通过安装器的更新命令或重装流程获取更新；具体选项以已安装版本的 `npx skills --help` 为准。更新可能替换 Skill 目录内的脚本和模板，发现本地定制时先报告差异，由用户决定是否保留或合并。

更新入口 Skill 不会同步改写目标项目中的 `AGENTS.md`、`PRODUCT.md` 或 `.githooks/`。补齐缺失项目文件可再次运行随 Skill 安装的初始化脚本；同步已有文件需要逐项展示差异并得到用户对改动的明确要求。

## 新建模板的完善

只根据用户提供的产品目标、已存在的代码和真实可运行命令填写新建模板。`pre-push` 默认不执行任何构建；应由目标项目按实际技术栈配置。已有文件缺少信息时，给出建议，不以模板代替它。
