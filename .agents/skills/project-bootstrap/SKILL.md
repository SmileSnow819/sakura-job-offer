# 初始化 AI 协作项目

目标是在新项目中建立最小、清晰、可维护的协作上下文，让 AI 能理解产品意图和工程边界，而不是套用一份通用大仓库规范。

## 调查现状

先阅读或检查：

- `PRODUCT.md`：用户、问题、核心范围、明确不做的事和产品原则。
- 现有 `AGENTS.md`、README、架构文档和目录结构。
- 技术栈与包管理器、构建、lint、typecheck、测试、运行和 CI 配置。
- Git 状态、已有 `.githooks/`、Git config 与现有 hook manager。
- 数据、权限、部署、迁移和外部服务等高风险区域。

如果没有 `PRODUCT.md`，创建短模板并请用户补充核心产品信息；不要凭代码或项目名发明用户、商业模式或功能范围。

## 建立文件职责

将事实放到正确位置：

| 文件或目录        | 应记录什么                                   |
| ----------------- | -------------------------------------------- |
| `PRODUCT.md`      | 做什么、为谁做、范围、原则和当前阶段         |
| `AGENTS.md`       | 开发规则、真实命令、架构边界、测试和文档要求 |
| `.agents/notes/`  | 代码无法直接解释且未来会影响选择的决定       |
| `.agents/skills/` | 只有该项目需要的专属流程                     |
| `.githooks/`      | 不应依赖 AI 记忆的最低 Git 规则              |

跨项目通用的方法属于个人 Skill 仓库，不要复制到每个项目的 `AGENTS.md`。

## 编写或完善 AGENTS.md

只写会改变 Agent 决策的项目事实。通常包括：

- 开始前必读的产品和架构文件。
- 实际可运行的 build、lint、typecheck、test、开发服务命令。
- 模块所有权、依赖方向、数据模型、公开 API 和安全边界。
- 何时必须向用户请求决定：产品范围、不可逆数据操作、外部写入、部署、密钥或权限升级。
- 文档、Agent Notes、快照和验证的最低要求。
- 项目的语言和双语文档策略。

不要放泛泛的“写干净代码”“多写测试”或与项目无关的框架规则；它们不会帮助 Agent 做具体选择。

## Git Hooks

优先使用仓库内 `.githooks/` 并通过 `git config core.hooksPath .githooks` 启用，使规则可提交、可审查、换机器后可恢复。

- `commit-msg` 只校验提交信息等快速、确定的规则。
- `pre-commit` 只运行低成本检查，例如格式化或 staged lint。
- `pre-push` 运行 build、typecheck 或快速测试等成本更高的验证。
- CI 运行完整测试矩阵、端到端测试和发布检查。

不要覆盖已有 hook manager 或已有 hooks；先识别项目已有约定，再选择集成、保留或让用户决定。

## 安全完成条件

- 初始化可重复运行，并保留所有目标项目已有文件。
- 每个新增文件有明确 owner 和用途。
- hook 脚本兼容项目使用的 shell，并完成语法检查。
- AGENTS.md 中的命令来自实际项目配置；不确定时标注待确认而非编造。
- 输出已创建、保留和待用户填写的内容，以及任何需要用户选择的地方。
