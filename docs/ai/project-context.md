# 项目背景与协作偏好

这份文档供新对话快速了解项目，记录已明确的协作习惯与当前产品边界，不是自动恢复聊天的记忆库。用户本次明确指示优先；涉及代码事实时，以仓库实际实现为准。不要将下面的项目偏好推广成用户在所有项目中的偏好。

## 项目在做什么

Sakura Job Offer 是校招资源与投递进度记录网站。主要包含公司/招聘入口目录，以及用户自己的公司、岗位、招聘阶段和导出记录。前端使用 React、TypeScript、Vite+；资源目录与本地投递数据是两类不同数据。

## 已明确的协作习惯

- 主要用中文交流，可以直接给截图、口语需求和具体反馈；AI 负责整理，不要求用户先写一篇完整 PRD。
- 较大的功能先讨论范围、流程与验收条件，再实施；用户已经确认的方案不要反复要求确认。
- 喜欢渐进式调整：先完成能看、能用的一小部分，再根据反馈迭代。收到新要求时先判断是在补充还是替换旧要求。
- 重视真实页面和视觉效果，反感模板化、装饰堆叠的“AI 味”。应结合所在页面与参考图确认方向，不擅自把整个网站改成统一灰色或统一渐变。
- 录入操作尽量简单，减少必填字段；能自动推断或延后补充的信息，不把负担转给用户。
- 代码必须有正常缩进、换行与结构；关键业务规则用中文解释原因，不接受靠把代码压成一行来缩短文件。
- 提交按功能拆开，便于检查与回退。每次只提交用户指定的范围，不附带无关数据或其他任务的改动。
- 状态说明要具体：做了什么、验证了什么、还差什么。不能把“计划更新文档”说成“文档已更新”。

## 当前产品边界与非显然规则

以下是本项目当前约定，可以由后续需求调整，不是永久禁令：

- 本轮投递管理不需要深色模式；不要仅因为通用设计指南提到深色模式就增加它。
- 新增投递以公司与岗位为核心；自定义公司官网选填，用官网自动获取图标，失败时使用文字头像，不强制上传 logo。
- 默认流程可自定义，每条投递保存独立阶段副本；修改默认模板不能改变已有记录。
- 普通最后一轮完成不等于拿到 offer；只有明确的 offer 阶段完成才计为已拿 offer。
- 投递记录保存在当前浏览器 localStorage，没有登录或云同步。不能因为换端看不到数据就自动清空或重建存储。
- 导出默认保护私人备注，用户选择后再包含；修改导出时同时检查长文本、空数据、多页与 HTML/CSV 转义。
- “电影海报风格”是曾提出的方向，不是已经验收的状态。继续相关工作时重新查看实现和参考图，不能根据这份背景宣布完成。

## 开发与验证约定

具体编码规则见 [项目开发 Skill](../../.agents/skills/sakura-project-conventions/SKILL.md)，命令与工具链约束见 [Vite+ Skill](../../.agents/skills/vite-plus/SKILL.md)。不要在这里复制全部规则。

- 使用项目锁定的 Node 与 pnpm；测试仍由 Node 原生测试框架运行，不用 `vp test` 替代投递测试。
- 代码检查不能代替业务场景测试；单元测试不能证明海报好看或按钮真的可用。
- 视觉验收应看实际页面或导出文件；涉及数据写入的测试使用明确的测试记录或隔离环境，保护用户真实数据。
- 暂无完整的“所有功能已验收”结论；新任务根据改动风险重新验证，而不是引用上一轮的通过记录。

## Git、自动化与权限

- 用户要求 commit 时按逻辑拆分；不等于允许 push、合并或部署。
- 仓库有 [提交信息检查脚本](../../.githooks/commit-msg)，要求 `类型(可选范围): 中文主题`，主题不超过 50 字；允许类型以脚本为准。脚本存在不代表当前 checkout 已启用，先用 `git config --get core.hooksPath` 检查；不要为文档任务修改 Git 配置。
- [Pages 工作流](../../.github/workflows/deploy.yml) 在推送 `main` 时执行检查、测试、构建和部署；它不是已经独立配置好的 PR 检查流程。
- 数据维护与前端开发分开处理。每日数据文件可能由其他任务维护，不能顺手格式化、暂存或删除。
- Superpowers 是项目内第三方 Skills，版本与来源记录在 [来源文件](../../.agents/superpowers-source.json)。不修改上游原文来记项目偏好，不擅自升级或启用全局配置。

## 什么应该持久化

- 用户明确确认的持续性习惯：更新本文，写明适用范围。
- 单个功能的目标、取舍、验收：写入该功能设计或计划，不加入长期偏好。
- 未完成任务的实际进度：使用 [交接模板](../ai-development.md#切换新对话时如何交接)，记录日期、分支、改动文件、验证结果与下一步。
- 不保存账号凭据、真实投递私密内容、临时绝对路径或无关聊天原文。只保留下一次继续工作真正需要的信息。
